# ADR 0009: Build iOS With Xcode 27 on SDK 57 Through Expo's Scene Support

**Date:** 2026-11-18
**Status:** Accepted

## Context

App Store Connect accepted build 1.1.1 (22) with warning ITMS-90725. The build used the iOS 26.5
SDK, and from April 2027 Apple accepts uploads only when they are built with the iOS 27 SDK
(Xcode 27) or later. Every EAS iOS build so far used the `macos-tahoe-26.5-xcode-26.6` image, pinned
in `eas.json` since 2026-09-23 and the image Expo's `sdk-57` alias points to.

Changing the image alone is not enough. Apps built with the iOS 27 SDK must use the UIKit scene
lifecycle, or they do not launch on iOS 27. The app uses Expo SDK 57's template AppDelegate, which
creates its own window and starts React Native in `didFinishLaunchingWithOptions`: the older
lifecycle.

Expo offers two ways to adopt scenes:

- **SDK 57 with `ios.enableSceneSupport`** in `expo-build-properties`, added in `expo` 57.0.23
  (2026-09-15, expo/expo#50191). Expo's scene delegate starts React Native and forwards URLs,
  universal links, Handoff and quick actions back to the existing AppDelegate. It also rebuilds the
  launch options, so `Linking.getInitialURL()` still sees a link that cold-starts the app.
- **SDK 58** (2026-10-15), whose template uses scenes by default. It also moves React Native from
  0.86 to 0.88.

Two config plugins edit the AppDelegate: React Native Firebase App (`FirebaseApp.configure()`) and
React Native Firebase Auth (a `firebaseauth` guard in `openURL`). Expo's scene support says it
edits only the standard template AppDelegate. On 2026-11-18 the project had `expo` 57.0.1 and
React Native Firebase 25.1.0. The Mac used for local builds already runs Xcode 27.2.

## Decision

Stay on SDK 57 and turn on its scene support:

- Upgrade every Expo-managed package to its latest SDK 57 patch with `npx expo install --fix`
  (`expo` 57.0.33, `expo-build-properties` 57.0.23, React Native 0.86.3).
- Set `ios.enableSceneSupport: true` in the `expo-build-properties` block of `app.config.js`.
- Pin the `macos-tahoe-26.6-xcode-27.2` image for the `production` profile in `eas.json`. The
  `testflight` profile inherits it.

## Alternatives Considered

1. **Upgrade to SDK 58.** This is the long-term direction, and it makes `enableSceneSupport`
   unnecessary. It lost because it does far more than the deadline needs: React Native 0.86 to
   0.88; React Native Firebase from 25 to 27, which reopens the static linkage in ADR 0002; Google
   Sign-In from 16 to 17; behavior changes in `expo-notifications`, `expo-router` and
   `expo-file-system`; and R8 on by default in Android release builds, which reaches the Android
   build too. It is its own project.
2. **Keep the Xcode 26.6 image until April 2027.** No work now, but the deadline would arrive
   with the change still untested.
3. **Use an image alias (`latest` or `sdk-58`).** Both pointed at the Xcode 27.1 release candidate
   on 2026-11-18, and an alias moves to new Xcode versions with no change in this repository. An
   exact image keeps every build reproducible.
4. **Write a scene delegate by hand.** `/ios` is generated by prebuild and not committed (ADR 0002),
   so a hand edit does not survive. A custom config plugin would copy what Expo now ships.

## Consequences

**Firebase starts only because of mod order.** React Native Firebase 25.1.0 inserts
`FirebaseApp.configure()` above `factory.startReactNative(`, the line scene support deletes. It
inserts from a dangerous mod, which Expo runs before the AppDelegate mod, so the call stays in
`didFinishLaunchingWithOptions`. This was checked on 2026-11-18 by running the config's iOS mods
over Expo 57.0.33's template, not yet in a real prebuild. Newer React Native Firebase versions also
match `return super.application(...)` and do not depend on the order.

**Links and pushes need a device check before release.** These all now pass through Expo's scene
delegate and need checking on iOS 26 and iOS 27 phones: cold-start links, universal links
(`ganapps.com/ganaps/` and `/friends/`), Google Sign-In, Sign in with Apple, push permission,
foreground banners, and opening an event from a push.

**The patch upgrade reaches Android.** The same `package.json` builds Android, so Android release
builds get the new SDK 57 patches and React Native 0.86.3 too.

**`@react-native-async-storage/async-storage` is excluded from Expo's version check.** It has been
3.1.1 since the first dependency install (2026-07-01), and Expo's SDK 57 list expects 2.2.0, so
`npx expo install --fix` would downgrade it a major version. `expo.install.exclude` in
`package.json` keeps it out of the check. Revisit on the SDK 58 upgrade.

**SDK 58 removes the setting.** On SDK 58 `enableSceneSupport` does nothing, and prebuild warns
that it can be removed. Remove it during that upgrade, and choose a new image then.
